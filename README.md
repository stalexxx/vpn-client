# VPN Client

macOS-клиент для подключения к готовым профилям 3x-ui. Панель 3x-ui работает на Linux; клиент получает из неё список профилей и запускает Xray на Mac. В текущем варианте поддерживается VLESS с TLS и XHTTP. Клиент не устанавливает и не разворачивает саму панель.

## Режим подключения

Основной режим — глобальный TUN через Xray. Системный proxy/SOCKS-прототип больше не является основным способом подключения. После первого подтверждения macOS клиент устанавливает `vpn-tun-helper` как root LaunchDaemon. Helper запускает и останавливает Xray, управляет выбранной DNS-службой и восстанавливает исходный DNS после отключения или обнаружения падения Xray. Helper и Xray должны быть включены в app bundle в `Contents/Helpers/`.

Установка или обновление helper-а требует системной авторизации macOS. Пароль не сохраняется приложением. После установки приложение общается с helper-ом через Unix-сокет, доступный только UID установленного пользователя. Helper сверяет версию протокола с версией приложения и при несовпадении запрашивает переустановку с системной авторизацией.

## Модель доверия

Сокет ограничен одним UID, но это не изолирует приложение от других процессов того же пользователя: любой процесс с этим UID может отправить helper-у команду `start` и попросить направить системный трафик через произвольный VLESS-сервер. Секреты конфигурации хранятся в локальных файлах с ограниченными правами; запущенный root-helper держит активную Xray-конфигурацию в каталоге, доступном только root. Не запускайте под тем же macOS-аккаунтом недоверенные программы.

Helper ведёт root-журналы процесса и DNS в `/Library/Application Support/VpnClientHelper`. При восстановлении он сравнивает текущий DNS с исходным и применённым состояниями: если DNS изменился извне, helper оставляет настройки и журнал на месте, чтобы не перезаписать пользовательские изменения. Если Xray завершается неожиданно, helper удаляет запись и конфигурацию процесса и пытается восстановить DNS.

## Запуск и сборка

Запуск интерфейса для разработки:

```sh
cargo run --manifest-path src-tauri/Cargo.toml
```

Сборка основного бинарного файла и привилегированного helper-а:

```sh
cargo build --release --bin vpn-core --bin vpn-tun-helper
cargo build --release --manifest-path src-tauri/Cargo.toml
```

Для полноценного TUN-запуска соберите app bundle и разместите в `Contents/Helpers/` исполняемые файлы `vpn-tun-helper` и Xray той же архитектуры, что и приложение. Оба файла и все каталоги на пути к ним должны принадлежать root и не разрешать запись группе или другим пользователям; символические ссылки запрещены. Иначе установка и обновление helper-а будут отклонены. Bundle должен включать корректный `Info.plist` и быть подписан в соответствии с выбранным способом распространения.

В приложении задайте адрес уже работающей панели 3x-ui и загрузите профили. Токен панели хранится в macOS Keychain; клиентские профили сохраняются локально для последующих подключений. Сертификат HTTPS-панели должен проходить стандартную проверку. Для панели, доступной только через SSH, настройте ключ и проверенный ключ сервера в `known_hosts`.

## MCP

Пакет приложения включает MCP-сервер `/Applications/VPNClient.app/Contents/Helpers/vpn-mcp` с транспортом stdio. Он предоставляет две команды без аргументов: `vpn_connect` подключает выбранную в главном окне конфигурацию, `vpn_disconnect` отключает VPN. Приложение должно быть запущено под тем же пользователем, что и MCP-сервер; связь идёт через локальный Unix-сокет в закрытом пользовательском каталоге. При первом подключении может потребоваться системное подтверждение установки TUN-helper-а. Для удалённого подключения можно запустить сервер через SSH в stdio-режиме под пользователем приложения.

При проверке на тестовой машине сравните внешний IP до подключения, после `vpn_connect` и после `vpn_disconnect`. Для безопасного восстановления удалённого управления используйте отдельный канал доступа, который останется доступен при смене маршрутов. Смена IP проверяет внешний адрес конкретного запроса и не заменяет проверки DNS и IPv6.
